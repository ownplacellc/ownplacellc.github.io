## 6. AI Studio: Server-Based Writing and Narration

This section applies only if you subscribe to AI Studio and use it.

### 6.1 No account — an Apple-signed transaction instead

There is still no account. When you subscribe, Apple gives the App a
transaction record signed by Apple. The App attaches that signed record to
every AI Studio request. Our server verifies Apple's signature and reads from
it only: the subscription's **original transaction identifier** (a number
assigned by Apple that stays the same across renewals and devices), the
**product identifier**, the **environment** (production or sandbox), and the
**expiry and revocation dates**. The signed record itself is not stored on our
server; the original transaction identifier is stored with your orders, your
permission records, and your hours ledger as the label of "whose subscription
paid for this."

The original transaction identifier is a purchase identifier: it contains no
name, email, Apple ID, or device identifier. **Apple does not provide your
identity with the transaction identifier. We may associate it with contact
information you voluntarily provide in support or privacy correspondence.**
Apple can identify you from it, and Apple treats it under Apple's own privacy
policy. Because it is a persistent, subscription-level identifier, we treat it
as personal information (a "User ID" in Apple's App Privacy terminology) and
every right in Sections 10–14 applies to it.

The App also sends a **shared service token** that is the same for every copy
of the App. The shared service token is a coarse abuse-control signal and is
not user authentication or proof that an unmodified App sent the request.
Authorization for subscription data and books depends on successful
verification of the Apple-signed transaction. With book orders, the App also
sends a **random order key** that lets the server recognise a repeated request
as the same order. The random order key is a pseudonymous order identifier: it
does not directly reveal your identity but is linked to the corresponding
order while that order exists.

### 6.2 What our server stores about an order

For each book you order or ask us to narrate, our service keeps one record
containing: your request text (for written books) or the text you supplied
(for narration), requested length, language, generated title and chapter
text, narration file names and durations, technical state and timestamps,
the original transaction identifier, the quota window it was charged to, and
the seconds of audio charged. Records live in a Modal Labs data store; audio
files live on a Modal Labs storage volume. For each writing-mode order, the
record also contains the technical request identifiers returned by
OpenRouter.

The order text, the generated chapters, the title, and the audio are held as
**temporary working storage** only for the time needed to run and deliver the
order: encrypted, subject to an application-level time-to-live, and excluded
from OWN PLACE LLC's application logs and crash reports. We do not create
separate content backups. Processor backup copies, if any, are handled as
described below. They are deleted as described in Section 6.4 ("no
post-delivery server retention").

Separately, for each subscription we keep the **permission records** described
in Section 6.6, the **hours ledger** described in Section 6.4, and, if you
have reported content or we have had to act on abuse, a **note of that
action** (book identifier, date, reason category, and the resulting
restriction, if any).
